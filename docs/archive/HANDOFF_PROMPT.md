## What SACRED is (architecture, in brief)
An **adversarial (asymmetric zero-sum) deep-RL framework** for the Stochastic & Dynamic VRP: a **protagonist** central dispatcher (truck fleet) vs an **antagonist** that injects road congestion under a budget (`antagonist_reward = −protagonist_reward`). Algorithm: **Soft Actor-Critic** (off-policy, max-entropy, with a replay buffer) trained via **ATLA** (alternating phases — one agent trains while the other is frozen). State = a graph observation featurized into a **PyTorch-Geometric GATv2** graph; policy/value heads on top. Real **OpenStreetMap graph** (Kaliningrad, 290 nodes / 412 edges). Thesis objectives: (1) the zero-sum game formulation; (2) the sim env; (3) SAC+ATLA + **ERB bootstrapping via metaheuristics**; (4) **SBO** for facility-location/fleet; (5) evaluation vs SOTA metaheuristics; with **Zero-Shot Transfer** as the crown-jewel claim. **Training is CPU-locked** (M4, 10 cores, 24 GB; MPS re-confirmed ~2.4–4× slower for this small-graph GNN).

## Project development over time — FACTS, with our interpretations LABELLED
*(Read the interpretations as the prior agents' reasoning, open to your challenge — not as settled.)*

**1. Origin + machinery debugging.** The codebase was first built with Google Gemini; a prior Claude session audited/de-risked it. Fixes that are now trusted: the **SAC alpha (temperature) loss had an inverted sign** in both agents → α ran away (1→69), critic Q exploded (7→601), policy stayed uniform (the 2000-ep run diverged) — fixed to `log_alpha*(H − H_target)` + `target_entropy=None` discrete fallback + `clip_grad_norm_=10`. Batched `update()` (encoder/head split, `tests/test_batched_equivalence.py`) — **honest measured speedup ~1.45×, not the 5–8× first projected** (on CPU, batching a GNN only removes Python overhead). MPS ruled out.

**2. The pivot (the original problem was "too easy").** On the original static-demand OSM problem, the `Value/Protagonist_Q_Spread` diagnostic (max−min Q across allowed destinations) **collapsed 5.3→0.46**, delivery rate sat **flat at ~0.91** across every reward variant, and policy entropy never fell. *Data:* demand was spread across 95/290 nodes (~1–2 pkg each). *Interpretation (prior):* per-step decisions were near-inconsequential (many equally-good nearby destinations), so RL couldn't beat a naive coverage policy, and the antagonist was toothless. → led to `PROBLEM_REDESIGN.md`: a **dynamic, multi-depot, latency-objective** VRP reached via a curriculum. *(Worth re-examining: was "too easy" the right diagnosis, or a symptom of something else?)*

**3. Stage 0 — single-truck next-hop route-choice (DONE).** A single truck, one target, a two-route corridor; the policy picks each edge (so the antagonist's congestion is a learned, exploitable choice). *Data:* it learns a consequential adversarial policy (Q_Spread rises 0.85→1.58, entropy commits, antagonist co-evolves) but **only *matches* greedy under attack**, and the eval gap oscillated. *Interpretation (prior):* single-truck route-choice vs a *reactive* greedy that reroutes optimally is structurally near-a-wash; headroom should live in multi-truck **assignment** where greedy is provably suboptimal.

**4. Static-3b assignment probe — a claimed milestone, then RETRACTED.** n=2 depots, contested static demand, destination-mode assignment (env auto-routes via Dijkstra). *Data:* a single run (`assign_probe_claimfix`) was read as "**first time RL beats a classical baseline**" (−6.5% under attack, best −22%) after fixing a double-assignment bug. **Later retracted:** a windowed re-read of its 20 eval points gave **mean `gap_atk` +18 (a loss)**, range [−188,+170]; the −56/−188 were the favourable *tail*. The eval metric was **mis-specified** (a single deterministic episode of learned vs the *co-evolving* antagonist → the ±100 swing is arms-race timing, not robustness), and per-phase checkpoints weren't saved so it couldn't be re-measured. *Lesson banked:* never headline a final/best point — use windowed means; measure vs a *fixed* adversary, not the co-evolving one.

**5. Experiment-management infrastructure.** Built to stop single-run self-deception: seeded "generations" (`scripts/run_generation.py` + `aggregate_generation.py`, `--seed`/`--group`/`--threads`, a ledger in `experiments/` pinning git SHA + a decision-metric fixed in advance), a **pre-training headroom gate** discipline (`scratch/*_headroom.py`), **best-checkpoint** selection, and **fixed-adversary / multi-instance** evaluation. Methodology dogma: **≥3 seeds, mean±std, decision metric fixed before looking, never compare across git states.** (See SYSTEM.md.)

**6. Stage 1.5 — dynamic (Poisson) assignment (`gen02_dynassign`) — DONE, near-wash.** The assignment lever moved into the dynamic regime: Poisson arrivals (λ=0.06, ρ≈1) on a contested hotspot band, 2 depots, destination-mode, latency, capacity-1. Two latent bugs were found+fixed while getting here (the antagonist's congestion *level value* was hardcoded `[0.25,0.5,0.75,1.0]` in `select_action` and the SAC `update` parse), and an antagonist-phase compute blow-up was fixed (budget → ~133 congestion sub-actions/ep, each an SAC update → antagonist phase 6.6× slower; capped to 1 block/event + full-blockage). *Interpretation (prior):* the machinery is sound but RL doesn't beat greedy — the **same near-wash as Stage 0 and static-3b**; with the env auto-routing, the antagonist only degrades *service rate*, and assignment-only can't beat greedy's reactivity. *(This is the crux to challenge: is "destination-mode is too thin" the real cause, or are the metrics/adversary/geometry the problem?)*

**7. Chokepoint analysis of the graph (facts).** `scratch/find_chokepoints.py` (edge betweenness + bridges + detour). **8. Stage 2 — hybrid (assignment + next-hop routing) — BUILT H1–H6, NOT TRAINED.** The protagonist interleaves *assignment* (pick a request → sets `assigned_target`) and *next-hop routing* (choose each edge toward it — the policy owns the path, so congestion is exploitable). `routing_mode="hybrid"`; GNN head unchanged.
